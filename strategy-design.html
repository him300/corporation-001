Strategy slots for traders and the maker

Give every participant a swappable strategy: today's Jev question, a rule from a paper, or a proper market-making model for Aurelia — without touching sizing, fills, impact or P&L. The engine already has the two seams this needs. This page is the layout and the contract, for you to accept or reject before I write it.

01 The seam that already exists

A trader's entire output is one number, intent, used at market.mjs:357. The maker's entire output is one pair, { mult, skew }, consumed by rebuild(m, mult, skew) at line 97. A strategy is anything that produces those.

Amber marks what becomes pluggable. The right-hand column must not move — it is where the simulator's honesty lives: the dead zone, the fill, the impact, the mark. Blue is just the file:line where each of those sits.

02 The contract

One file exports a registry. Nothing else in the app knows strategy names; the engine asks the registry for entry.posture() and keeps its own code path. 

// strategies.mjs — proposed
export const STRATEGIES = {

  'mom.jev': {
    agent: 'mom', kind: 'model', version: 1,
    brief: (ctx) => ({ state, question }),        // exactly today's brief()
  },

  'mom.ema': {
    agent: 'mom', kind: 'rule', version: 1, source: '—',
    needs: ['closes', 'sigma'],
    params: {                                       // [min, max, default] → auto-rendered UI
      fast: [3, 20, 8],
      slow: [10, 60, 24],
      volGate: [0, 3, 1.2],
    },
    decide(ctx, p) {
      const z = (ema(ctx.closes, p.fast) - ema(ctx.closes, p.slow))
              / (ctx.sigma * Math.sqrt(p.slow) || 1);
      if (Math.abs(z) < p.volGate) return { side: 0, strength: 0 };
      return { side: Math.sign(z), strength: Math.min(1, Math.abs(z) / 2) };
    },
  },

  'mm.fixed': {                                 // today's maker, unchanged
    agent: 'mm', kind: 'quote', version: 1,
    quote: (ctx) => ({ mult: 1, skew: 0 }),
  },

  'mm.as': {                                    // Avellaneda–Stoikov, §04
    agent: 'mm', kind: 'quote', version: 1, source: 'Avellaneda & Stoikov (2008)',
    params: { gamma: [0.1, 20, 5], kappa: [5, 120, 25], horizon: [5, 60, 20] },
    quote(ctx, p) {
      const v = p.gamma * ctx.sigma ** 2 * p.horizon;
      const r = ctx.mid - (ctx.inventory - ctx.target) * v;      // reservation price
      const half = v / 2 + Math.log(1 + p.gamma / p.kappa) / p.gamma;
      return { mult: (half * 2) / baseHalf(ctx.mid), skew: r - ctx.mid };
    },
  },
};

A quote strategy returns the same two numbers the Jev-based maker already produces (line 351), so rebuild() needs no knowledge of it. params as [min, max, default] is what lets the UI render sliders and validate input without a second schema.

04 The maker, properly

What Aurelia does today is a one-parameter inventory skew plus a width the Jev votes on. That is the degenerate case of the standard inventory model — so the upgrade is a family, not a rewrite.

r = s − q · γ · σ² · (T − t) reservation price δ = γ σ² (T − t) / 2 + (1/γ) · ln(1 + γ/κ) half-spread bid = r − δ ask = r + δ
sthe mid. Already in state.
qinventory minus target — position − 4000, already computed at line 339.
σper-round volatility. Estimate as an EWMA of realised mid returns; today's replay already computes stdev.
T − trounds of horizon. A policy choice, not an estimate.
γrisk aversion. The dial: γ→0 reproduces a flat 8 bp quote.
κfill intensity decay. As γ→0 the half-spread tends to 1/κ, so κ sets the floor; at γ = 5, κ ≈ 22.6 lands on today's 4 bp half.

Two properties worth noticing before you accept it. The reservation price tilts the whole quote, not just the width — long inventory quotes lower on both sides, which is what makes the position mean-revert instead of drifting. And the spread has a floor 1/κ: the model cannot quote tighter than its assumed fill rate, which is the honest way to encode “I don't know how fast I get filled here”.

What maps to what. Today: mult = Jev-voted 0.6–2.2, skew = −(position−4000)/4000 × 0.035. Under A–S the same two fields become mult = 2δ / baseHalf and skew = r − mid. The ladder, tape, P&L and every screen keep working — that is the acceptance test: switching the maker strategy must not require a new renderer.

07 Money, attribution, honesty

The moment decisions come from more than one place, three things quietly become lies unless the design prevents it.

ProblemWhat I would do
P&L stops meaning anythingAttribute per strategy: a switch writes a strategy event to the tape with a round number, and P&L is reported since the switch, not since the session.
The bill silently changessnapshot().bill gains a modelCalls / ruleCalls split. A round with two rules costs three calls, not five — that should be visible, not inferred.
A run is no longer reproducibleRule strategies are deterministic given seed, so replay becomes reproducible for the first time. Model strategies are not, and the UI should say which is which.
Nobody remembers which version ranEvery decision carries { strategy, version, paramsHash }; the snapshot button already freezes a round to JSON — it now freezes the config too.

One thing I would refuse to fake. A paper's algorithm is usually calibrated against real order flow: fill probability as a function of distance, queue position, adverse selection. This simulator has one maker, a book rebuilt with random resting sizes every round, no queue and no latency. So κ can only be assumed, not estimated — which means A–S here is shape-faithful and intensity-approximate.

That is fine for the question “does this class of policy behave differently from that one”, and it is not fine for “this is what the paper's author measured”. The design should print that distinction next to the strategy name rather than let a reader assume otherwise.

08 How I would build it

  1. Increment 1 — the registry, rules only

    Registry, params, indicator helpers, trader-side rule strategies, the switcher, per-strategy P&L attribution and the bill split. The maker is untouched, so the riskiest surface stays frozen while the seam is proven.

    gate — switch mid-run with no restart; attribution adds up; an untouched run is byte-identical

  2. Increment 2 — maker strategies

    mm.band, mm.as, mm.glt, plus the quote panel with the live derivation (r, δ, the two terms). σ estimated from the session's own mid returns, EWMA.

    gate — q = 0, κ ≈ 22.6 reproduces today's 8 bp; the ladder and tape render identically under every maker

  3. Increment 3 — the comparison harness

    One CSV, N strategies, one table: return, vol, delta, tracking error, direction agreement, path ρ. This is the part with research value — the strategies are just the subjects.

    gate — the same CSV run twice with rule strategies produces identical numbers

09 What I need from your papers

Send a paper and I will fill this in. The fields are what the contract needs; anything that has no answer in a paper is a design decision you should make, not something I should invent.

FieldWhy the engine needs it
State variablesOnly what the state can supply — otherwise needs gains a field and freshMarket() must start tracking it.
Parameters + rangesBecomes params: [min, max, default] and the UI sliders. A parameter with no range cannot be swept.
OutputAn intent scalar, or a quote { mult, skew }. Anything else needs a new seam and a longer conversation.
EstimatorsHow σ, κ, λ or a fill probability are measured. In this simulator they come from the tape or they are assumed — say which.
Assumptions that break hereQueue priority, partial fills, latency, competition. Marking these keeps the fidelity column honest.

Fidelity, up front, so nothing gets oversold: A–S and GLT — shape faithful, intensity approximate. Ho–Stoll skew — already the current behaviour, faithful. Almgren–Chriss — faithful in replay, where a real cost model exists. OFI / queue-sensitive models — low fidelity; the book here is texture, not a record of who wants to trade. I would label those “experiment only” in the UI rather than let the name imply more than the harness can carry.

What I need from you to start: yes to the seam in §01, a decision on whether switching is allowed mid-run or only at reset (§07), and the first paper. Everything else in this document is reversible; those three are not.
